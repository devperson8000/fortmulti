# HCS implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution, with an independent final code review.

**Goal:** Add the approved HCS experience without changing polished gameplay.
**Architecture:** Pure schedule/ranking/tournament rules feed an authenticated durable referee service. An isolated lobby controller handles nickname, promotion, ranking/check-in and delayed viewing; small existing-app hooks route official matches to the unchanged simulation.
**Tech stack:** Existing browserESmodules, Node22, ws WebSockets, Supabase anonymous authentication/service-role storage, existing Match and native collision maps.
**Spec:** ../specs/2026-10-09-hcs-design.md

## Global constraints
- Schedule1Nov2026Sunday19:00Australia/Sydney, every21calendar days;20second viewer delay; top5/reserves6–9; nickname only.
- Preserve map/model/audio/core movement files. Official results require a trusted server, not browser score submissions.
- Live configuration is absent: distinguish tested local service from activated production.

## Review focus
- DST/date boundaries and48h freeze must retain the sameedition.
- Concurrentcheck-ins/rejoins never admit6competitors or duplicate anidentity.
- Viewer sockets never receive current snapshot/input powers or early champion results.
- Forged names/results/rosters and duplicategame completion never alter legitimate rankings.
- Ordinaryplay without HCSservice remains usable and polished regressions stay green.
